# Лабораторная работа 1: клиент для Coffee API

Небольшой Python-клиент на `requests` для публичного API горячих напитков:
https://pycourse-2026.duckdns.org/coffee/hot/


## Запуск

```bash
pip install requests
python coffee_client.py
```

Программа сама создаёт тестовую запись с уникальной меткой, проходит
по ней весь сценарий и удаляет её. Чужие записи не затрагиваются.

## Что делает программа

| Шаг | Запрос | Что проверяется | Статус |
|-----|--------|-----------------|--------|
| 1 | GET `/` | список приходит массивом | 200 |
| 2 | POST `/` | создание, `id` берётся из ответа | 201 |
| 3 | GET `/{id}` | данные совпадают с отправленными | 200 |
| 4 | PUT `/{id}` | заменились все поля | 200 |
| 5 | PATCH `/{id}` | изменилось только `description` | 200 |
| 6 | GET `/{id}` | остальные поля остались прежними | 200 |
| 7 | DELETE `/{id}` | запись удалена | 200 |
| 8 | GET `/{id}` | запись не найдена | 404 |

## Устройство кода

- `_request()` выполняет все HTTP-запросы, задаёт тайм-аут, отличает 404
  от других ошибок и превращает ошибки сети в `CoffeeApiError`.
- `_read_json()` проверяет `Content-Type` и корректность JSON.
- `validate_drink()` проверяет значения до отправки (непустые строки,
  состав `ingredients`, отсутствие неизвестных полей).
- Блок `finally` в `main()` удаляет созданную запись, даже если сценарий
  упал на середине.
- Повторы запросов не реализованы: после тайм-аута POST неизвестно,
  создалась ли запись, поэтому программа выводит метку для ручной проверки.

Описание запроса создания лежит в докстринге в начале `coffee_client.py`.
